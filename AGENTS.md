# AGENTS.md

## Project Purpose

This repository is the exercise output workspace for the **Multi-Agent Try-Out** workshop.

It contains two hands-on tracks:

1. `session-1-github-copilot-agent`
2. `session-2-copilot-cowork`

When making changes, treat this repository as training material that should stay easy to follow for workshop participants.

## Core Instructions

- Reason internally in English.
- Write learner-facing content in Thai unless a file already uses English for a specific reason.
- Prefer small, clear edits that preserve the current workshop flow.
- Keep file and folder names stable unless a rename is explicitly required.
- Do not remove or relocate sample assets unless the task clearly asks for it.
- For Microsoft-related exercise content, validate claims against the latest official Microsoft documentation before finalizing edits.

## Content Style

- Keep instructions practical and step-by-step.
- Favor short sections, checklists, and direct action wording.
- Preserve the beginner-friendly tone used in the existing `README.md` files.
- If you add a new exercise, explain the goal, prerequisites, steps, and expected outcome.

## Repo Structure

- `README.md`: main workshop landing page and session index
- `provided-account.md`: shared participant account details
- `session-1-github-copilot-agent/`: developer-focused exercises
- `session-2-copilot-cowork/`: business-user-focused exercises
- `assets/` folders: screenshots and visual references used by instructions
- `files/` folders: downloadable sample materials for exercises

## Official Source Validation

- Treat the latest official Microsoft content as the source of truth for Microsoft product behavior, UI labels, prerequisites, licensing notes, availability notes, and workflow steps.
- Before editing or approving Microsoft-related exercise content, re-check the relevant official pages on the same day of the change instead of relying on repo text alone.
- Prefer official Microsoft Learn pages first, especially for Microsoft 365 Copilot and Cowork content.
- For Cowork-related exercises, validate against the latest versions of:
  - `https://learn.microsoft.com/microsoft-365/copilot/cowork/get-started`
  - `https://learn.microsoft.com/microsoft-365/copilot/cowork/use-cowork`
  - `https://learn.microsoft.com/microsoft-365/copilot/cowork/whats-new`
- When Microsoft documentation and current repo wording differ, update the exercise content to match the official docs unless the repo is intentionally documenting a tenant-specific exception. If it is tenant-specific, call that out explicitly in the content.
- Validate concrete details, not just overall concepts. This includes current entry URLs, navigation labels, approval behavior, side-panel terminology, task flow, file handling, and licensing or admin prerequisites.
- If a Microsoft feature is changing quickly, prefer wording that stays accurate longer and avoid brittle UI instructions unless the current label has been re-verified from official docs.
- Record the validation date in your summary when you make material Microsoft-content changes.

## Change Rules

- Update the root `README.md` if you add, remove, or rename an exercise.
- Keep links relative and repo-friendly so the content works on GitHub.
- Verify image references and local file paths after editing Markdown.
- Avoid adding unnecessary tooling, build steps, or repo-wide complexity.
- Do not mark Microsoft-related exercise edits complete until the latest official Microsoft source check is done.

## Definition Of Done

Before finishing a task, make sure:

- the edited instructions are easy to scan,
- links and referenced files still exist,
- Microsoft-related claims were revalidated against the latest official Microsoft documentation when relevant,
- the workshop flow remains coherent for participants,
- and the repo still reads like curated training material rather than raw notes.
